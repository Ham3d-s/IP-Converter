## 2024-05-18 - [SSRF Bypass via DNS Resolution Flaws]
**Vulnerability:** A basic string-matching SSRF protection mechanism on user-provided hostnames is easily bypassed via DNS trickery (e.g., DNS rebinding or simply using a custom domain pointing to `127.0.0.1` like `localtest.me`).
**Learning:** `new URL(customBaseUrl).hostname` only parses the string—it does not inherently resolve the underlying IP. Even when `dns.resolve(hostname)` is added, it must check for both IPv4 (`resolve4` or default `resolve`) and IPv6 (`resolve6`), or specifically use `dns.lookup(hostname, { all: true })` to get all addresses. In Node.js, `dns.resolve()` fails with `ENODATA` if the specific record type (e.g. `A`) doesn't exist even if another (e.g. `AAAA`) does, potentially allowing execution to continue if the error is caught and swallowed.
**Prevention:** Always validate all resolved IPs using `dns.lookup({ all: true })` or explicitly check both `A` and `AAAA` records. Do not catch and swallow native DNS resolution errors silently; if a domain doesn't resolve or errors out during safety checks, it should be treated as unsafe or explicitly blocked. Additionally, directly check the string if it's already an IP address to avoid unnecessary DNS lookups and potential bypasses.
